---
title: WildClawBench Migration
description: Notes for migrating WildClawBench into Harbor with parity-oriented task generation.
---

WildClawBench is migrated through a parity adapter in `adapters/wildclawbench`.
The adapter preserves the upstream task contract instead of rewriting tasks into
a generic Harbor `/app` layout.

## Source Layout

The upstream repository is expected at
`related-projects/external-tasks/WildClawBench`. Tasks are Markdown files under
`tasks/<category>/`, while large workspace data is downloaded separately from
the Hugging Face dataset.

Before generating the Harbor dataset, prepare the upstream workspace. Prefer the
explicit include form so every nested workspace file is fetched:

```bash
uvx --from "huggingface_hub[cli]" --with "httpx[socks]" --with socksio \
  hf download internlm/WildClawBench \
  --repo-type dataset \
  --local-dir related-projects/external-tasks/WildClawBench \
  --include "workspace/**"
```

If your environment uses a SOCKS proxy, include `socksio` and `httpx[socks]` as
shown above. Without them, the Hugging Face or ModelScope clients may fail with
`ImportError: Using SOCKS proxy, but the 'socksio' package is not installed`.

Then run the upstream preparation script, which downloads/derives the large
video assets, SAM model weights, and safety-task git fixtures:

```bash
cd related-projects/external-tasks/WildClawBench

uv run \
  --with yt-dlp \
  --with modelscope \
  --with socksio \
  --with "httpx[socks]" \
  bash script/prepare.sh

cd ../../..
```

If YouTube asks for sign-in or bot confirmation, put cookies in the standard
`yt-dlp` config file before rerunning `prepare.sh`:

```bash
mkdir -p ~/.config/yt-dlp
printf '%s\n' '--cookies-from-browser chrome' > ~/.config/yt-dlp/config
```

If YouTube extraction reports missing formats or challenge-solving failures,
install a JavaScript runtime for `yt-dlp`:

```bash
brew install deno
uvx --from yt-dlp yt-dlp \
  --js-runtimes deno \
  --list-formats "https://www.youtube.com/watch?v=93LPZJkCW2w"
```

Two upstream tasks intentionally have no agent-visible `exec/` workspace:
`01_Productivity_Flow_task_1_arxiv_digest` and
`01_Productivity_Flow_task_9_scp_crawl`. The adapter allows those in strict
mode. Other missing `exec/` paths generally mean the Hugging Face workspace
download or preparation step is incomplete.

Load the upstream base image:

```bash
uvx --from "huggingface_hub[cli]" --with "httpx[socks]" --with socksio \
  hf download internlm/WildClawBench \
  --repo-type dataset \
  --local-dir related-projects/external-tasks/WildClawBench \
  --include "Images/wildclawbench-ubuntu_v1.3.tar"

docker load -i related-projects/external-tasks/WildClawBench/Images/wildclawbench-ubuntu_v1.3.tar
```

Then build the Harbor derivative that preserves the upstream image contents
while replacing the cached OpenClaw binary:

```bash
bash adapters/wildclawbench/docker/openclaw/build.sh
```

The upstream image contains stale proxy variables, so the build script clears
proxy settings by default. Set `BUILD_HTTP_PROXY` and `BUILD_HTTPS_PROXY`
explicitly if your Docker build needs a reachable proxy.

## Harbor Mapping

Each WildClawBench task becomes a one-step Harbor task. The step layout lets
Harbor run upstream warmup commands before the agent starts.

- Agent-visible files come from upstream `workspace/.../exec`.
- Hidden ground-truth files from upstream `workspace/.../gt` are copied only to
  Harbor `tests/`.
- Requested skills are copied from upstream `skills/` into `/skills` in the
  generated environment.
- The generated environment uses the derived
  `wildclawbench-ubuntu-openclaw:2026.5.27` image by default, sets
  `/tmp_workspace` as the workdir, and symlinks `/app` to `/tmp_workspace`.
- Generated Dockerfiles include `FROM --platform=linux/amd64 ...` because the
  upstream WildClawBench image tarballs are amd64-only.
- The embedded upstream `grade(...)` function is executed directly during
  verification.

## Running

Generate tasks:

```bash
uv run python adapters/wildclawbench/src/wildclawbench_adapter/main.py \
  --output-dir datasets/wildclawbench \
  --link-assets \
  --overwrite
```

Use `--link-assets` for full local generation unless you intentionally want a
second physical copy of the prepared WildClawBench workspace. The prepared
workspace is large, and hardlinks keep Docker-visible files as normal files
without duplicating their contents on the same filesystem.

Run with the default config, which mirrors the PinchBench job model settings:

```bash
uv run harbor run -c examples/configs/wildclawbench-job.yaml
```

The default config uses OpenClaw with `anthropic/kimi-k2.6` and the verifier
model `glm-5.1`. The generated verifier aliases `OPENROUTER_*` variables from
`ANTHROPIC_*` variables when only the PinchBench-style config is present.

The WildClawBench upstream base image includes an older cached OpenClaw binary.
The derived image caches `OpenClaw 2026.5.27`; the example config pins the same
version so Harbor verifies the cache and skips per-run installation.
