---
title: ClawBench Migration
description: Notes for migrating ClawBench Core public tasks into Harbor.
---

ClawBench is migrated through `adapters/clawbench`. The adapter targets the
Core v1 public manifest at `related-projects/external-tasks/clawbench/tasks-public/MANIFEST.yaml`.

## Source Layout

The upstream repository is expected at `related-projects/external-tasks/clawbench`.
The public task directory contains 27 YAML files, but only 19 are part of the
Core v1 manifest. The adapter uses the manifest as the default source of truth,
so perturbed YAML variants are not generated unless support is added later.

## Generate Tasks

```bash
uv run python adapters/clawbench/src/clawbench_adapter/main.py \
  --output-dir datasets/clawbench \
  --overwrite
```

Use `--link-assets` when generating on the same filesystem and you want to avoid
duplicating the public asset packs.

## Harbor Mapping

Each manifest task becomes a Harbor task. Public asset packs are copied into
`environment/workspace/`, and generated environments use `/workspace` as the
workdir with `/app` symlinked to `/workspace` for compatibility.

Single-user ClawBench tasks become one Harbor step named `run`. The memory
continuation task becomes `prep` and `implementation` steps; the final step
provides the trial reward.

The verifier runtime is copied into each task's `tests/` directory. It scores
ClawBench completion checks, process trajectory, behavior expectations, and the
optional rubric judge. It writes a flat `/logs/verifier/reward.json` containing
the Harbor `reward` plus numeric `clawbench.*` component scores. Rich ClawBench
details such as delivery outcome strings, assertion traces, trajectory details,
and judge rationales are written to `/logs/verifier/clawbench_details.json`
because Harbor reward values must be numeric.

The default base image is the pinned OpenClaw image used by upstream ClawBench.
It is currently amd64, so generated Dockerfiles use `FROM --platform=linux/amd64`.
They also include `HEALTHCHECK NONE` because Harbor replaces the container
command with `sleep infinity`; inheriting OpenClaw's app healthcheck would make
Docker Compose report the idle task container as unhealthy.
The generated environment installs the Playwright browser and the Node
`playwright` package under `/workspace/node_modules` so verifier scripts can use
`require("playwright")`.

## Judge Configuration

Judge calls default to the same GLM-oriented configuration as PinchBench and
WildClawBench. Anthropic-compatible gateways can use:

```bash
ANTHROPIC_API_KEY=...
ANTHROPIC_BASE_URL=...
MODEL_NAME=glm-5.1
```

OpenAI-compatible gateways are also supported:

```bash
OPENAI_API_KEY=...
OPENAI_BASE_URL=...
MODEL_NAME=glm-5.1
JUDGE_API_FORMAT=openai
```

`OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL`, and `JUDGE_MODEL` are accepted for
parity with the WildClawBench job configuration. `JUDGE_API_FORMAT` can be
`auto`, `anthropic`, or `openai`; `auto` selects OpenAI format when `OPENAI_*`
judge variables are provided.

## Running

```bash
uv run harbor run -c examples/configs/clawbench-job.yaml
```

Official-style ClawBench reliability requires three attempts per task. The
example config intentionally uses one attempt for local smoke runs.
